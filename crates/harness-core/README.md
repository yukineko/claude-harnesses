Do not use `hook::run_hook` for a hook that returns a decision: use `gate::run::run_guarded` for a Stop gate and `hook::run_pretooluse_guarded` for a PreToolUse gate.

harness-core ships no `plugin.json`, no hooks, and no binary.

- `store`: Per-project note store; its fallback lookup does not return another session's tagged note and writes bytes atomically under concurrent writers.
- `hook`: Hook stdin payload struct and the `run_hook` wrapper, which catches a panic in the handler, logs it to stderr and prints no decision.
- `hook_latency`: Append-only Stop-hook latency ledger that writes one line per recorded call and aggregates per session with a per-hook breakdown. Its ledger is `<base_dir("harness")>/state/hook-latency.jsonl`.
- `install`: `~/.claude/settings.json` hook installation: command-marker ownership detection, replacing the plugin's own groups while keeping foreign ones. Writing settings first leaves a timestamped `.bak-` copy of the old file.
- `hash`: FNV-1a 32-bit and 64-bit hashes pinned to known vectors.
- `projkey`: Per-project key `<basename>-<fnv1a32-hex>`.
- `config`: Tilde expansion (`~`, `~/x`) and a dot-prefixed base dir under home.
- `gate::runner`: Subprocess runner that flags a timeout and keeps only the last lines of output.
- `gate::state`: Per-session attempt counter that increments within its window and resets after an idle gap.
- `gate::run`: `run_guarded` panic barrier **fails closed**: a panicking gate body blocks the first stop with a `{"decision":"block"}` payload; a panic while `stop_hook_active` is set (a re-entered stop, whatever blocked the previous one) is allowed through; an interactive run takes precedence over `stop_hook_active`. The one-shot skip is consumed once and is invisible to other sessions. A panic in an interactive run exits 1.
- `gate::protection`: The `Protection` statement carries `protects`, `against` and `grounds` fields.
- `spans`: Defensive JSONL span loader that skips malformed lines and reports how many.
- `session`: Per-session record that round-trips through upsert and load, including the per-agent breakdown. The record is stored at `<state_dir>/sessions/<id>.json`.
- `usage` / `transcript`: Transcript token aggregation per model, with the 5m/1h cache-write split and tool counts.
- `estimate`: `estimate_transcript_cost` returns the same cost as `usage::aggregate` followed by `pricing::session_cost`; an unknown model makes the cost undetermined. `estimate_transcript_cost` is re-exported at the crate root.
- `metrics`: Append-only JSONL metrics sink that writes one line per `emit`.
- `pricing`: Model-to-USD cost table with cache read/write multipliers; an unrecognized model with usage is undetermined, not $0.
- `ledger`: Daily spend ledger: a session's cost is summed into the day total and re-recording the same session overwrites it; a corrupt file is an error and is preserved. The default state dir is `~/.budgetguard/state`, holding `ledger.json`.
- `daily`: Once-per-calendar-day guard: runs on first use, not again after `mark_done`, and again on a new date.
- `inject`: Layered config for context-injection hooks: project overrides global overrides default, and a character budget caps what is admitted.
- `inject_metrics`: UserPromptSubmit injection-size metrics; its `turn_key` is stable and changes with the session or the prompt.
- `interrogate`: Gate-by-gate interrogation control structure whose source contains none of the listed direct-IO tokens such as `std::fs`, `std::net` and `std::process::Command` and which sentinels at the round limit.
- `shell`: Shell invocation: `sh -c` on Unix, `cmd /C` on Windows.
- `trust`: Workspace-trust store: a project is untrusted until added, `add` is idempotent, `remove` reverses it.
- `scorer`: Deterministic priority scorer: referentially transparent, same input gives the same bits; monotone in severity and effort; out-of-range `goal_proximity` is clamped to [0, 1]; the `L2`/`L5` lenses outrank the others. `score` (re-exported at the crate root) is exactly `severity_weight × clamp(goal_proximity, 0.0, 1.0) ÷ effort_factor × lens_multiplier`.
- `verdict`: Three-valued gate `Verdict` (`Clean` / `Violation` / `Undetermined`): no findings is `Clean`, any finding is `Violation`; `Undetermined` blocks exactly like `Violation`; fabricating a `Clean`, a `Default` or a `From<bool>` is a compile error.
- `boundary`: Fallible input boundaries return `Determination`: an unreadable directory is `Undetermined`, not an empty `Vec`, and a non-zero subprocess exit keeps its code and gates stdout on it.
- `undetermined`: Constructing a `Verdict::undetermined` or `Determination::undetermined` records one line with its reason, and a `Verdict::undetermined` line names the caller's file.
- `degrade`: Verdict-monotonicity property: a clean verdict from degraded evidence is a violation, while holding or tightening is fine.
- `git_probe`: Git-repository probe that reports `Undetermined`, not "not a repo", when git fails but `.git` exists, and "not a repo" when git fails and no `.git` exists.
- `primary_tree`: Three-valued primary/linked working-tree classification by git-dir vs git-common-dir; `refuse_if_primary` treats `Undetermined` as a refusal.
- `attribution`: Only files a peer session claims and this session does not are excluded; an unreadable transcript narrows nothing.
- `repeat`: Session-scoped repeat ledger: the first occurrence of a finding stands and the second yields; a missing session id is undetermined, not a repeat. A yielded Stop block prints one line, `{"systemMessage":"<gate>: 同じ指摘の2度目のため通しました（未解消）"}` (no reason text; the full reason is in the session's `waivers.log`).
- `fleet`: Canonical fleet GATE-crate name set (`GATE_CRATES`) and `BLOCKING_GATES`, a superset of it.
- `autonomy`: Autonomy switch: mode parses only `on` and `off`, and the switch-file payload round-trips.
- `parallel`: Session-wide concurrency ceiling of 3, never exceeded by `clamp` and floored at 1.
- `plugin_bin`: Locates a sibling plugin's executable from the plugin cache, picking the newest version numerically, and, when the cache holds no version directory, reports a binary absent from `$PATH` as known-absent rather than undetermined.
- `progress`: Liveness engine: any advancing signal is `Progressing`, a fingerprint frozen across the window is `Stalled`, and a first observation is undetermined, never stalled.
- `append`: Atomic single-`write()` JSONL append: one newline-terminated record per call, and concurrent writers never interleave records.
- `discovery`: Append-only discovery-record store: a record persisted by one session is seen as owned by another session's lookup, with a deterministic fingerprint.
- `lessons` / `retrieval`: Lessons store idempotent by id, first write wins, and a retrieval-event ledger idempotent by run id. The default lessons store is `~/.lessons/lessons.jsonl`.
- `code_index` / `text_index` / `callgraph` / `index_store`: Lexical indexes: deterministic symbols, deterministic full text and a caller-to-callee graph that finds edges across files, with a façade that answers symbol search and full-text search.
