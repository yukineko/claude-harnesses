# backlog タグ規約（クロスプロジェクト共通）

> 複数プロジェクトで繰り返し検出される作業種別に共通タグを与え、`backlog list --tag <tag>` /
> `overwatch` / `scout` 側での横断集計・再発検知を可能にするための規約。プロジェクト固有の
> `--tag scout` 等のソース由来タグとは別軸で、**作業内容の分類タグ**として付与する。

## タグカテゴリ

- **worktree-hygiene** — worktree の作成・削除・切り替え漏れ、branch の孤立・stale化、
  `condukt` の worktree ライフサイクル管理不備など、リポジトリ作業ツリー衛生に関する作業。
  複数プロジェクト（aegis `f5e98fc4` / ai-aegis `0111925f` /
  ai-agent-tenant-toggle-api `d0732c8a` / wasabi-repair-flask-decouple `11764f7c`）で
  同型の課題として繰り返し検出され、このタグへ retag 済み。
- **deploy-verify** — デプロイ後の疎通確認・ヘルスチェック・ロールバック判断など、
  本番/ステージング反映後に「動いていることを確認する」工程の不備・自動化不足に関する作業。
- **network-infra** — VPC/サブネット/セキュリティグループ・DNS・ロードバランサ等、
  ネットワーク経路そのものの設定・疎通に起因する作業（アプリケーションコードの不具合とは区別する）。

## 運用ルール

- 既存 backlog エントリが上記カテゴリに該当すると判明した時点で `--tag <category>` を付けて
  retag する（新規追加時に限らない）。
- 1 エントリに複数タグを付けてよい（例: `--tag worktree-hygiene --tag scout`）。
- 新しい繰り返しパターンを見つけたら、このファイルにカテゴリを追記してから retag する
  （タグだけ先行させて説明を後回しにしない）。
